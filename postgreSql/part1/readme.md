## realtional database:

- stores data in tables and can connect multiple tables using relationships to fetch data.
- we should use relational db when we have clear structure of the predefined, we have realtionships and want to join tables, we want transactions, we want strong validation at db level, etc.
- banking ecom, CRM, ecom, etc

## non-relational database:

- doesnt organise data in tables, it uses documents and key-value pairs.
- we should use non-relational database when our changes very often, documents are independent, not needed relations/joins, etc.
- blog app, etc
